# T0 契约：训练前四个决策的交付物与验收方式

> 原则：**Tier 0 的产出不是"结论"，是"可复核的证据 + 一个待批准的推荐"。**
> 每一项都必须有：① 一个能被我复跑的脚本或校验器；② 固定结构的决策记录；③ 明确的接受/拒绝判据。
> 执行者（gqq）只允许：读代码 / 跑脚本 / 写指定的新增文件。**禁止**改引擎、改已有测试、改 `deviations.md`、`git commit`。

---

## D-A 训练栈（**需要人拍板，gqq 只出对比材料**）

- 交付：`docs/decisions/D-A-training-stack.md`（≤ 1 页），固定小节：
  1. 候选（≥3 个）与各自依赖清单（必须列出会新增的第三方包）
  2. 与现有接口的摩擦点：明确回答"`CardEnv` 需要提供哪 4 个函数"
  3. 最小可行实现的行数估计 + 主要风险
  4. 推荐与**反悔成本**（换栈要重写哪些文件）
- 验收：小节齐全；依赖只允许 `torch` / `numpy`（其余需说明理由）；不得出现未经验证的性能断言。
- 人工判据：**你只需回答"选哪个"**，其余由我核对。

## D-B 卡组池（**需要你先定来源**）

- 交付：`decks/train/*.json` 6 套 + `decks/test/*.json` 3 套 + `scripts/verify_decks.py`
- 校验器必须检查：3 角色 / 30 张牌 / 同名 ≤2 / 角色不重复 / 所有名字存在于本仓库的 208 张卡与 47 个角色 / 训练集与测试集不完全相同
- 验收：`python scripts/verify_decks.py` 退出码 0；9 套牌全部通过
- ⚠️ 风险：gqq 无外网，**不能凭记忆编卡名**（会幻觉）。它只能从 `mode.all_cards()` / `mode.all_chars()` 里挑，由校验器兜底。
- 人工判据：牌表"像不像一套能打的牌"只能你判断——这是设计决策，不是代码正确性。

## D-C 观察表示（**可机器复核 → 可以交给 gqq**）

- 交付：`analysis/probe_observation_layout.py` + `docs/decisions/D-C-observation.md`
- 脚本必须输出：
  1. 2778 维的**分段表**：`[起, 止] → 语义名`，段与段之间**无缝无重叠**，合计 = 2778
  2. 每段：长度、采样 200 个决策态后的**取值基数**、是否常量
  3. 提议的分组：每组 → 段列表 + 词元数，总词元数 ≤ 256
- 验收（我复核）：
  - 分段表覆盖 `0..2777` 恰好一次
  - 算术与 `GameState.encoding` 一致：`4(basics) + P1 段 + P2 段 + 效果段 = 2778`
  - 常量维数量与"裁剪收益"数字一致（复跑两次相同）

## D-D 奖励 shaping（**可机器复核 → 可以交给 gqq**）

- 交付：`analysis/probe_phi_predictiveness.py` + `docs/decisions/D-D-reward-shaping.md`
- 脚本必须输出（≥200 局随机对局，固定种子列表）：
  1. 击杀率 / 超时率
  2. 至少 3 个候选 Φ 的**区分度**：`Φ(最后一次决策)` 预测"P1 最终获胜"的 AUC（只用击杀局）
  3. 候选 Φ 定义：`chars_only`、`hp_only`、`chars*10+hp`（后两者可再加权重变体）
- 验收（我复核）：
  - 同种子两次运行输出一致
  - 三率与 AUC 都是实测数字，不许出现"预计/应该"
  - 推荐必须给出**具体系数**（如 `0.1·(Φ(s')−Φ(s))`）与一条**可反驳的预测**（"若 shaping 有效，则 M2 前 10^5 交互内超时率应下降 ≥X%"）
