# D-D：奖励 shaping（势函数 Φ）

status: accepted（2026-10 用户拍板：**λ = 1e-3**，即保守档；默认关闭，见 §5）
date: 2026-10
判据脚本：`analysis/probe_phi_predictiveness.py`（400 局固定种子 `0..399`，6 条预登记判据，本轮全绿）

---

## 1. 决策（三句话）

1. **Φ 只由公开信息构成**：`Φ = 10·(自己存活角色数 − 对方) + (自己总血量 − 对方总血)`，
   经 `perspective_view(seat)` 取值，对席位严格反对称。不看手牌、不看牌序。
2. **shaping 形式**：`r_t = r_terminal + λ·(γΦ(s′) − Φ(s))`，`γ = 0.99`，**λ = 1e-3**。
   实测 Φ 的量程 89–93，所以整局 shaping 总量 ≤ 0.09，即 ≤ **9%** 的 `|r_terminal| = 1`。
3. **默认关闭**。开启必须同时满足 §5 的四个条件；任一不成立就退回 `λ = 0`。

---

## 2. 为什么 v1 的 `AUC = 0.996` 不能用

v1 用「**最后一次决策**的 Φ」预测「P1 最终获胜」，得 AUC ≈ 0.996。
这是循环论证：局终时 P1 若还有 3 个角色、P2 是 0 个，AUC 必然趋近 1。
它只证明"Φ 能读终局"，而 shaping 只在**终局之前**起作用。

本记录保留这个数字，但只作**读数健全性检查**（实测 0.9942 / 0.995）。真正的判据换成
「进度 25% 处的 Φ 预测终局」。

---

## 3. 实测（400 局，`RandomAgent`，固定 seed）

### 3.1 终局分布

| 项 | 值 |
|---|---|
| 击杀 | 132 局（33.0%），Wilson 95%CI ≈ [28.6%, 37.8%] |
| 超时（双方判负） | 268 局（67.0%） |
| 击杀局分配 | P1 胜 70 / P2 胜 62 |

> 另一轮同配置运行给出 116/284（29%/71%），300 局那轮是 28.7%/71.3%。
> 跨进程会有几个百分点的漂移（见 §6.1），所以这里只用"约 1/3 击杀、2/3 超时"这个量级。

### 3.2 早期区分度（仅击杀局，标签 = P1 是否获胜）

| 进度 | AUC | 95%CI（Hanley–McNeil） | 解释 |
|---|---|---|---|
| 10% | 0.61（另一轮 0.51） | — | 该点 Φ 大量并列（多数为 0），**不稳定，不采用** |
| **25%** | **0.67**（另一轮 0.64） | [0.58, 0.76] | **判据点**：Φ 已携带信息 |
| 50% | 0.73（另一轮 0.79） | — | 信息更强，但此时已接近终局 |
| 终局 | 0.995 | — | 循环论证，仅作读数检查 |

**由这张表得出的唯一结论**：Φ 在进度 1/4 处就有可测的区分度（CI 下界 > 0.5），
所以把它当 shaping 目标是**有信息可依**的；但 10% 处不可用 —— 因此**不做分期规则**
（原计划的"前 10% 不加 shaping"被这轮数据否掉，理由是该点两次运行差了 0.10）。

---

## 4. 泄漏检测：这才是真正的护栏

Φ 的失效模式不是"没信息"，而是"**偷看**"——一旦 Φ 读了对方手牌/牌序，策略就会学成
"用不该知道的信息做决策"，在真机上崩掉。检测做法：

1. 取 40 个决策态，把**对方牌堆顺序反转**（纯隐藏信息，任何公开字段都不变）；
2. 要求 `phi_public` 前后**逐位相同**；
3. 同时用**故意的作弊版** `phi_leaky`（额外读对方牌堆顶 3 张）作**正对照**，要求它**必须变化**。

实测：`phi_public` 改变 **0/40**，`phi_leaky` 改变 **39/40**，反对称违例 **0/40**。
正对照有 1 例未变，最可能是牌堆不足 3 张时反转不改变"顶 3 张"的内容 —— 这是已知盲点，
所以判定用"正对照必须至少变一次"，而不是"必须全部变"。

> 这条检测的价值在于它会**失败**：如果把 Φ 写成从 `full_view()` 取，它立刻会红。

## 5. 开启条件（缺一不可）

| # | 条件 | 为什么 |
|---|---|---|
| 1 | **当前策略下**重测 `AUC@25% ≥ 0.60` | 本文的 0.67 是随机策略上的数；策略一变，Φ 的信息量就会变（这正是 v1 的错） |
| 2 | 泄漏检测通过（公开版 0 改变 + 正对照有变） | §4 |
| 3 | 幅度：`λ·max|γΦ′−Φ| ≤ 0.05·|r|` | 实测最大单步 16.8 ⇒ `1e-3 × 16.8 = 0.017` ✓ |
| 4 | **M2 的可反驳预测成立** | 见下 |

### 可反驳的预测（M2 一并验收）

> 同种子、同超参、**只差 λ**（1e-3 vs 0）：shaping 组在前 `1e5` 交互内的 `timeout_rate`
> 应比对照组低 **≥ 5 个百分点**，且两者 Wilson 95%CI 不重叠。

若不成立 → 把本记录标 `rejected`，`λ` 永久置 0。**不许**用"再调调系数"来解释失败。

## 6. 风险与已知失真

1. **跨进程漂移**：同 seed 两次运行，击杀率 29% vs 33%。原因见 D-C §6：引擎对类对象集合的
   迭代顺序依赖进程内 `id`。所以本文所有数字只用于**方向与量级**，不用于精确复现断言。
2. **Φ 忽略资源**（骰子/手牌/能量），可能引导"苟血不进攻"。而 timeout 是双方判负，
   本身就惩罚苟血 —— 两股力互相拉扯，只能靠 §5.4 的 `timeout_rate` 检验，不能靠直觉。
3. **AUC 是相关性不是因果**：shaping 可能被 hack。缓解是 λ 取小（≤9% 的终局奖励）
   且必须与基线对照，而不是"加了 shaping 就更好"。
