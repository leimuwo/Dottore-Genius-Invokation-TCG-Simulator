# D-C：观察表示

status: proposed
date: 2026-10
判据脚本：`analysis/probe_observation_layout.py`（120 局打满，17 998 个决策态；7 条判据全绿，
1 条预登记假设被推翻，见 §5）

---

## 1. 决策

| 项 | 决定 |
|---|---|
| 逐决策观测 | **实体对齐词元**：每个活着的实体 1 个词元 + 少量动态标量 |
| 静态内容（牌表 `initial_deck`、角色定义、max_hp/element/weapon/id） | 挪到**每局一次**的上下文向量，不进逐决策 |
| 填充位 | 直接丢弃（实测 1 271 维） |
| 词元预算 | 实测 p50=41 / p90=47 / **p99=50** / max=56；上限 256，余量 ≥5× |
| v1 的「每段 1 个词元 = 26 词元」 | **否决** |

实体→词元映射：手牌每张 1；角色每只 1（138 维字段过小 MLP）；状态/summon/support 每个 1；
骰子 1（8 种元素计数向量）；deck/used/gained 各 1（集合池化）；效果栈每层 1；`game_basics` 1。

观测按席位取（`perspective_view(seat)`），与 D-A 的 `obs(seat)` 对齐。

## 2. 为什么 v1 的两条结论被撤

### 2.1 「常量维 2538、可裁到 247」是采样假象

v1 每局只取**前 4 个决策态**（共 480 个样本），那时手牌少、效果栈空。
打满整局（17 998 个决策态）后：常量维是 **2 219**，而且不是一个数而是一个结构：

| 类别 | 维数 | 含义 |
|---|---|---|
| **P 填充位** | 1 271 | 容量 − 占用；永远为 0 |
| **S 静态位** | 1 044 | 局内从不变化，跨局才变（卡牌定义/牌表内容） |
| **D 动态位** | 463 | 局内变过 → 必须逐决策观测 |

同一脚本对「前 4 态」口径给 2 569、对全量给 2 219，**差 350 维**——这就是假象的量级（判据 C5）。
所以"裁到 247"既不成立也没有意义：真正要问的是"这 2 219 维分别是什么"，而不是"能删多少"。

### 2.2 「26 个词元」粒度不够

把 1000 维效果栈段、414 维角色段各压成 1 个词元，模型分不清"哪个角色被打残"。
换成实体对齐后 p99=50：量级翻倍，但仍远低于 256。

## 4. 三个实现时必须知道的坑

1. **填充位在尾部，但那是当前实现的巧合**：卡牌 code 先升序、再追加 0；骰子/状态/效果栈同理。
   按位置切"尾部 0"能work，但这不是接口契约 —— 所以策略层用实体对齐 + 容量校验，不硬编码下标。
2. **`num_cards()` 会说谎**：`Cards` 里允许出现**负计数**（实测 `ChangingShifts: -1`），
   于是 `num_cards()=sum(values)` 比真实张数少，而 `encoding` 按 `Counter.elements()` 给真实张数。
   实测 **57/17 998** 个决策态触发（0.32%）。本脚本改为**从编码本身数占用**，
   并把"负计数"作为独立引擎问题（E5）登记，不在本决策里修。
3. **效果栈在决策态几乎总是空的**：p50=0、p99=5、max=10；但**解析过程中**最大深度到 **20**
   （测试套件实测）。所以"效果栈 → 10 个词元"是决策态的上限，不要为它做很重的编码器。

## 5. 判据与结果

| 判据 | 结果 |
|---|---|
| C1 分段覆盖 0..2777 各一次 | PASS |
| C2 每段 容量 × 字段宽 == 段长 | PASS |
| C3 ≥120 局且 ≥12 000 决策态 | PASS（17 998） |
| C4' 容量公式给出的填充位 100% 落在"局内恒定"里 | PASS |
| C5 前 4 态口径 − 全量口径 ≥ 100 维 | PASS（350） |
| C6 词元 p99 ≤ 256 且 max ≤ 320 | PASS（50 / 56） |
| C7 同进程重跑逐位一致 | PASS |
| **H1（预登记假设）填充位 ≥95% 的常量维** | **推翻（实测 57.3%）** |

H1 被推翻是**结果不是缺陷**：填充位只解释 57% 的常量维，剩下的是静态身份字段 ——
这恰好支持 §1 的"静态内容挪进上下文向量"。判据（代码/不变量）与假设（关于数据）分开报，
免得以后有人为了让门禁变绿去改数字。

## 6. 已知失真

1. **跨进程漂移**：同一脚本跑三遍，P/S/D = 1 288/1 025/466、1 292/1 012/474、1 271/1 044/463。
   原因是引擎对"类对象集合"的迭代顺序依赖进程内 `id`。结论只用**量级与结构**（P≈1.3e3、
   S≈1.0e3、D≈0.47e3），不用精确复现断言。
2. **占用分布来自随机策略**：`RandomAgent` 的手牌/状态占用偏低（例如 supports 打到 4 个满）。
   换成会打的策略后占用会上升 → p99 词元数（50）是**下界**，M1 需重测一次，但仍远低于 256。
