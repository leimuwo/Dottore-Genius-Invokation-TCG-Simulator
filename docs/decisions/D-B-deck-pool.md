# D-B：卡组池

status: accepted
date: 2026-10
**来源决定**：用用户已经搭好的「6 训练 + 3 测试」牌表（`decks/train/*.json`、`decks/test/*.json`）。
不再去外网找牌表，也不由执行者自创。判定"像不像一套能打的牌"由人负责，机器只负责合法性。

---

## 1. 校验器与判据

`scripts/verify_decks.py`，10 条判据，任一 FAIL 退出码 1：

| # | 判据 | 为什么需要 |
|---|---|---|
| S1 | JSON 可解析且**无重复键** | `json.load` 会静默去重，重复键会悄悄吃掉牌 |
| S2 | `chars` 为 3 个字符串，`cards` 为非空 {名字: 正整数} | 结构 |
| S3 | 角色不重复 | 引擎不允许 |
| S4 | 牌总数 == `deck_cards_requirement()` | 30 张 |
| S5 | 同名 1..2 张 | 规则 |
| S6 | 名字全部存在于 `mode.all_chars()` / `all_cards()` | **防幻觉**：无外网时凭记忆写牌名必错 |
| S7 | `FrozenDeck.from_json` 能加载 | 训练侧直接吃文件走这条路径 |
| S8 | `mode.valid_deck(deck)` 为真 | 引擎自己的合法性判据（含每张牌的入组条件） |
| S9 | 牌表逐套不相同（同集合内 + 跨集合） | 否则"留出卡组"名不副实 |
| S10 | train ≥ 6 套，test ≥ 3 套 | 数量 |

## 3. 这个池子能回答什么

- **卡组条件化**：6 套训练牌表覆盖 水/雷/冰/草/岩/火 六种元素主轴 → 可以测"换牌表后还打不打得动"。
- **留出评估**：3 套测试牌表只在评估里出现 → 可以测**卡组级**泛化（不是角色级，见 §4）。
- **加载路径已钉死**：`FrozenDeck.from_json(路径文本)`，校验器与训练侧用同一条路径。

---

## 4. 已知局限（必须写进论文口径，别让结论超卖）

1. **测试集与训练集共享角色**：V7 与 T1 共有 `Fischl`+`RhodeiaOfLoch`，V8 与 T5 共有
   `AratakiItto`+`Mona`。只有 **V9 与所有训练集角色完全不重叠**。
   ⇒ 测出来的泛化是「卡组级」，**不是**「角色级」。
2. **通用牌包高度重叠**：9 套**全部**含这 7 张——`AdeptusTemptation` `LeaveItToMe` `Liben`
   `LotusFlowerCrisp` `Paimon` `SendOff` `Starsigns`。测试集与最相近的训练集**共有 12–13/30 张**。
   ⇒ 差异主要体现在 3 个角色 + 约 10 张「引擎牌」上；通用包的收益几乎可以完全迁移。
3. **全是 15 种 × 2 张**：没有 1 张的"对策牌"。所以牌表结构上 9 套完全同构，
   测不到"张数分布/单张"的影响。若以后要测，需要另建一套含 1 张卡的牌表。

## 5. 用法（与 D-E 对齐）

| 用途 | 用哪套 |
|---|---|
| 训练 rollout | `decks/train/` 6 套，按 D-E 的侧别配额采样 |
| 评估 | `decks/test/` 3 套 + 固定套件（同 `(deckA, deckB, seed)`，所有策略共用） |
| 报表 | 按 D-E/T7 的两张表（按卡组、按侧别）+ 超时率 + CI |
