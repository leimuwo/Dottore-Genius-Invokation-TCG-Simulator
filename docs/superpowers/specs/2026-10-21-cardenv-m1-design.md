# CardEnv M1 验收规格

用户已确认三步目标：补全接口、达到性能门槛、正式接口跑满 10,000 局。

## 边界

仅扩展 dgisim_ext、添加测试及 analysis 验收工具；保留现有未提交文件。
不改规则、牌表、受保护脚本或 CI，不进入 PPO。
验收发现必要的 E8 引擎编码修复：Status 字段按 dataclass 声明顺序编码；
只改两行，先取红再取绿，登记 deviations 并新增不变量测试。
继续使用 reset / obs / step / fork，合法动作按内容打分。

## 行为

- 重掷按元素选择 0..持有数量，换牌按种类选择 0..持有数量，覆盖全部子集。
- 付款按元素选择数量，只提供存在合法完成方案的候选；不枚举完整 PlayerAction。
- 观察包含部分选择及完整选择前缀，保证中间决策可辨识。候选携带无碰撞的内容特征。
- commit 检测非法返回、异常及无迁移；失败分类计数、终止该局并抛结构化错误，禁止伪装正常终局。
- reward 始终标注执行席位，终局输出双方奖励（超时 -1/-1）。
- 每环境保存独立 RNG 状态；fork 复制随机流，原环境和副本互不干扰。
- 编码按当前不可变状态和席位缓存，commit/reset 清空；中间 choice 不重复编码。

## 性能

保持 A3 平均 Obs <=1ms、A4 100,000 choice 步 <=300s 的已有门槛。
同时报告缓存命中、真实新状态编码与引擎耗时；另测禁用观察/候选缓存的完整 Obs。
禁止用热缓存冒充新态编码。
固定牌表、种子和策略，预热后串行重复三次，报告各轮结果。

## 稳定性证据

6 train +3 test 仅用于环境验证，不用于训练；有序卡组组合及席位均衡轮转。
策略 RNG 与引擎 RNG 分开。逐步记录候选内容、index、执行席位、奖励；逐局记录
种子、卡组、终局原因、异常类别。manifest 记录 Git HEAD、dirty 状态、源码与牌表 SHA256、参数。
先跑小批次及跨进程逐步 obs/choices/reward 摘要比较，再运行完整 10,000 局。
失败局单列并保留复现信息，不计为正常超时；任一三率非零不宣称通过。
报告 choice/s、commit/s、games/s、超时率、三率及 CPU 时间、编码时间。

## 测试

先写失败测试：全部骰子/换牌子集、付款可达性、错误分类、视角缓存失效、
reward 席位、fork 随机隔离与中间前缀。每阶段跑全量 unittest，不修改既有断言。
